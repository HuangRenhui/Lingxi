# 开发指南

## 1. 环境要求

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 8+ | 项目 `source/target` 为 1.8；已验证可用 JDK 21 编译 |
| Maven | 3.8+ | 建议配置阿里云镜像 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0 | 本地或 Docker |
| Redis | 6+ | 本地或 Docker，用于登录失败计数与令牌黑名单；故障时降级，非启动强依赖 |
| Docker | 可选 | 一键启动全部服务 |

## 2. 本地启动

### 2.1 初始化数据库

```sql
CREATE DATABASE IF NOT EXISTS lingxi
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;
```

导入表结构与种子数据（在项目根目录执行）：

```powershell
mysql -uroot -p lingxi -e "source backend/src/main/resources/db/schema.sql"
mysql -uroot -p lingxi -e "source backend/src/main/resources/db/data.sql"
```

> PowerShell 不支持 `<` 重定向；如需使用 `mysql ... < file.sql`，请在 cmd 中执行。

默认开发库连接为 `localhost:3306/lingxi`，账号密码请按本机情况修改 `backend/src/main/resources/application-dev.yml`。

### 2.2 启动 Redis（推荐）

```powershell
docker run -d --name lingxi-redis -p 6379:6379 redis:7-alpine
```

登录失败计数与令牌黑名单使用 Redis；Redis 不可用时登录限流降级为进程内计数，不阻断登录。

### 2.3 启动后端

确认 `JAVA_HOME` 指向 JDK（不是 JRE；已验证 JDK 21 可构建）：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\latest\jdk-21"
mvn -f backend/pom.xml spring-boot:run
```

- 接口地址：`http://localhost:8080/api`
- 健康检查：`http://localhost:8080/api/health`
- Knife4j：`http://localhost:8080/api/doc.html`

非 `dev` profile 必须设置 `JWT_SECRET`（至少 32 字节），否则启动失败；开发默认密钥只在 `application-dev.yml` 中提供。

### 2.4 启动前端

```powershell
cd frontend
npm install
npm run dev
```

- 页面：`http://localhost:5173`，登录后进入首页
- 管理后台：`http://localhost:5173/lingxi-console-7c3f/login`（演示账号 `admin / Admin@123`）
- 开发环境默认启用 Mock（自动跳过登录与后端校验）；连接真实后端时设置 `VITE_MOCK=false` 后重启
- Vite 将 `/api` 代理到 `http://localhost:8080`

### 2.5 Docker Compose 一键启动

```powershell
Copy-Item .env.example .env
# 修改 .env 中的 MySQL / Redis 密码与 JWT_SECRET（至少 32 字节）
docker compose up -d --build
```

| 服务 | 地址 |
| --- | --- |
| 前端 | `http://localhost` |
| 后端 | `http://localhost:8080/api` |
| MySQL | `localhost:3306` |
| Redis | `localhost:6379` |

MySQL 首次启动会自动执行 `schema.sql` 与 `data.sql`。修改初始化 SQL 后需删除 `mysql-data` 卷再启动。

## 3. 配置项

**后端与基础设施**

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `JWT_SECRET` | JWT 签名密钥，至少 32 字节；非 dev 必填，未配置会启动失败 | dev 使用 `application-dev.yml` 内置值 |
| `SPRING_DATASOURCE_URL` | 生产数据源 URL | 无，生产必填 |
| `SPRING_DATASOURCE_USERNAME` | 数据库账号 | 无，生产必填 |
| `SPRING_DATASOURCE_PASSWORD` | 数据库密码 | 无，生产必填 |
| `SPRING_DATA_REDIS_HOST` | Redis 地址 | `redis` |
| `SPRING_DATA_REDIS_PASSWORD` | Redis 密码 | 空 |
| `MYSQL_ROOT_PASSWORD` | Compose MySQL 密码 | 无，必填 |
| `REDIS_PASSWORD` | Compose Redis 密码 | 无，必填 |
| `CORS_ALLOWED_ORIGINS` | 允许跨域来源，逗号分隔，禁止 `*` 与凭据组合 | `http://localhost:5173,http://127.0.0.1:5173` |

**前端**（`frontend/.env.development` / `.env.production`）

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 请求前缀，开发环境由 Vite 代理 | `/api` |
| `VITE_MOCK` | 是否启用演示数据层；development 下未设为 `false` 时默认启用 | 开发环境 `true` |
| `VITE_ADMIN_PATH` | 管理后台隐藏路径 | `/lingxi-console-7c3f` |

后端配置文件：

- `application.yml`：通用配置（端口、上下文路径 `/api`、MyBatis-Plus、文档）；
- `application-dev.yml`：本地数据库 / Redis；
- `application-prod.yml`：环境变量注入，关闭接口文档。

## 4. 代码规范

### 4.1 后端

- 严格按 `controller → service → mapper` 分层，controller 不直接调用 mapper；
- 入参使用 `dto` + `javax.validation` 注解，出参使用 `vo`，禁止返回 `entity`；
- 业务失败抛 `BusinessException`，由 `GlobalExceptionHandler` 统一转换；
- 需要登录态的接口通过 `SecurityUtils.getUserId()` 获取用户，并校验资源归属；
- 新增 Redis Key 统一写入 `RedisKeys`；
- 数据库变更同步维护 `db/schema.sql`、`docs/数据库设计.md`；
- 公共方法必须写清业务含义，简单 getter/setter 不写注释。

### 4.2 前端

- 请求封装放在 `src/api`，一个后端模块一个文件；
- 统一走 `utils/request.js`，不要在页面里直接使用 axios；
- 登录态读写统一走 `utils/auth.js` 与 Vuex `user` 模块；
- 对话应用、创作工具、首页分类与精选作品统一登记在 `src/config/tools.js`，页面从注册表读取，不硬编码名称、图标与参数；
- 新页面在 `src/views` 下按业务建目录，统一复用 `components` 下的 PageHeader、TabStrip、StatCard、EmptyState 等基础组件；
- 样式优先使用全局变量（`--app-primary`、`--app-bg`、`--app-border` 等），页面样式加 `scoped`。

### 4.3 Git 提交

采用 Conventional Commits，scope 对应模块或层：

```text
feat(auth): 增加登录接口
feat(agent): 支持任务启停
fix(security): 修复过期令牌未清理上下文
docs(api): 补充任务接口示例
chore(docker): 调整后端健康检查
```

建议：

- 一个提交只做一件事；
- 后端、前端、文档改动分批次提交；
- 提交前至少执行 `mvn -DskipTests compile` 与 `npm run build`。

8 个对话应用为 `chatgpt`、`claude`、`gemini`、`grok`、`deepseek`、`kimi`、`qwen`、`doubao`，统一走 `/chat/:app`。

### 5.1 新增一个创作工具

1. 在 `frontend/src/config/tools.js` 的 `tools` 数组增加一条配置，至少包含 `key`、`path`、`title`、`category`、`icon`、`description`、`model`、`price`、`resultType`、`fields`；
2. 路由、左侧图标栏与通用创作页自动生效：路由由 `tools` 生成，页面按 `meta.toolKey` 渲染；
3. 需要在首页分类中出现时，把 `key` 加入 `toolCategories` 对应分组的 `tools`；需要作为精选作品展示时，在 `showcases` 增加带 `toolKey` 的记录；
4. 参数控件由 `fields` 决定：`type` 支持 `select`、`segmented`、`ratio`、`upload`、`switch`、`number`、`text`、`textarea`、`tags`、`modeTabs`；`promptIndex` 控制提示词位置，`visibleWhen` 控制条件显示；需要新控件时在 `views/create/fields/FieldRenderer.vue` 增加分支。

无需新建页面或路由文件，任务与画廊会按工具 `key` 自动隔离存储在 `localStorage`。

### 5.2 新增一个对话应用

1. 在 `frontend/src/config/tools.js` 的 `chatApps` 增加一项：`key`、`path: '/chat/<key>'`、`title`、`model`、`models`、`icon`、`description`；
2. `/chat/:app` 为通用路由，无需新增路由；左侧图标栏与首页分类会自动读取；
3. 如需出现在首页「和 AI 对话」分类，把 `key` 加入 `toolCategories` 中对话分组的 `tools`；
4. 会话按应用隔离存储，`views/workspace/index.vue` 从 `route.params.app` 读取当前应用。

### 5.3 新增一个管理后台页面

1. 在 `frontend/src/views/admin/<page>/index.vue` 创建页面，复用 `PageHeader`、`StatCard`、`TablePager`；
2. 在 `frontend/src/router/index.js` 的后台路由分组中注册 `path: '<page>'`，标记 `meta.admin: true` 与标题；
3. 在 `layout/admin.vue` 的 `navGroups` 对应分组增加菜单项（分组顺序：总览、用户与运营、交易、内容与合规、平台配置、数据）；
4. 数据接入方式二选一：先在 `mock/admin.js` 或 `mock/admin-extra.js` 增加演示数据与读写方法，待后端就绪后改为 `api/` 调用；
5. 页面中的表格统一加分页，筛选条件变化时重置到第 1 页。

### 5.4 列表分页规范

```js
const page = ref(1)
const pageSize = 10
const paged = computed(() =>
  list.value.slice((page.value - 1) * pageSize, page.value * pageSize)
)

watch([keyword, status], () => {
  page.value = 1
})
```

```vue
<el-table :data="paged" size="small">...</el-table>
<TablePager v-model:page="page" :total="list.length" />
```

- 一个页面有多张表格时，各自维护独立的 `page` 与 `paged`；
- 卡片网格类列表（技能、连接器、精选作品）不使用分页；
- 不要手工修改固定列背景，统一由 `styles/index.scss` 的全局规则处理。

### 5.5 演示数据维护

- 新增演示数据时，在对应 `mock/*.js` 中定义默认值与 `load/save` 方法，键名以 `lingxi-` 开头；
- 用户端与后台共享的数据（兑换码、优惠券、模型目录）必须复用同一个存储键，避免两侧不一致；
- 新增的键需要加入 `mock/account.js` 的 `resetDemoState()` 清理列表，确保「清空演示数据」能完整重置；
- 生产构建如需关闭 Mock：构建时设置 `VITE_MOCK=false`。

## 7. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `No compiler is provided in this environment` | `JAVA_HOME` 指向 JRE；改为 JDK 目录后重试 |
| `Cannot create resource output directory ... target\classes` | `target` 目录被占用或权限异常；删除 `backend/target` 后重试 |
| 启动报 JWT 密钥未配置或长度不足 | 非 dev 环境未设置 `JWT_SECRET` 或少于 32 字节；配置至少 32 字节的密钥，开发环境可用 `application-dev.yml` 默认值 |
| 登录返回 401 | 令牌过期或 `JWT_SECRET` 变更；清理浏览器 `localStorage` 重新登录 |
| 登录返回 2004 / 提示锁定 5 分钟 | 同一用户名连续 5 次登录失败触发限流；等待 5 分钟或成功登录后自动清除，Redis 故障时使用进程内计数 |
| 启动报数据库连接失败 | 检查 MySQL 是否启动、库是否存在、`application-dev.yml` 账号密码 |
| 前端请求跨域 | 开发环境使用 Vite 代理；直连后端时检查 `CORS_ALLOWED_ORIGINS` |
| Docker 中改 SQL 不生效 | MySQL 初始化脚本只在空数据卷执行；删除卷后重启 |
| Knife4j 打不开 | 生产 profile 默认关闭文档；本地使用 `dev` profile |
| 管理后台地址 404 | 核对 `VITE_ADMIN_PATH` 与访问路径，默认 `/lingxi-console-7c3f/login` |
| 管理后台反复跳回登录 | 管理员会话存于 `lingxi-admin-session`，可能被清除；重新登录或检查浏览器隐私模式 |
| 页面数据与数据库不一致 | 开发环境默认走 Mock；设置 `VITE_MOCK=false` 并重启开发服务器 |
| 清空演示数据后仍有旧内容 | 工具任务与会话按 `lingxi-tool-tasks-*` / `lingxi-chats-*` 分键存储，刷新页面；新增键需同步加入 `resetDemoState()` |
| 表格右侧操作列文字重叠 | 确认 `styles/index.scss` 中固定列背景规则未被页面局部样式覆盖 |
