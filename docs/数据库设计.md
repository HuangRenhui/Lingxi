# 数据库设计

## 1. 设计约定

- 数据库：MySQL 8.0，库名 `lingxi`，字符集 `utf8mb4`，排序规则 `utf8mb4_general_ci`；
- 主键：`BIGINT AUTO_INCREMENT`；
- 时间：`created_at` 默认当前时间，`updated_at` 自动更新；
- 删除：业务主表使用 `deleted TINYINT` 逻辑删除（0 未删除 / 1 已删除）；
- 金额：统一使用 `DECIMAL(18,6)`，禁止浮点；
- 状态：使用短字符串枚举（如 `ENABLED` / `DISABLED`），便于排查；
- 敏感信息（上游 Key、支付凭证）必须加密后存储，禁止明文。

初始化 SQL 位于：

- `backend/src/main/resources/db/schema.sql`
- `backend/src/main/resources/db/data.sql`（幂等种子数据）

### 3.2 计费字段约定

成本与收费必须分列存储，否则无法证明"用户扣费不低于上游成本"。

**`billing_rule`**

| 字段 | 说明 |
| --- | --- |
| `category` | `chat` / `image` / `video` / `music` |
| `price_in` / `price_out` / `price_cached_in` | 对话类三档售价（积分 / 1K tokens），命中缓存的历史上下文按第三档计费 |
| `price` | 非对话类单价（积分 / 张、秒、首） |
| `cost_in` / `cost_out` / `cost` | 上游成本，与售价同单位；接入后由「美元单价 × 汇率」换算写入 |
| `multiplier` | 加价倍率，实际售价 = 单价 × 倍率 |
| `effective_from` | 生效时间，调价不回溯历史订单 |

**`usage_record`**

| 字段 | 说明 |
| --- | --- |
| `request_id` | 幂等键，防止超时重试重复扣费 |
| `input_tokens` / `output_tokens` / `cached_tokens` | 上游返回的真实用量，推理 tokens 计入输出 |
| `unit_count` | 非对话类的计费量（张 / 秒 / 首） |
| `cost_amount` | 上游成本（按渠道成本价折算） |
| `charge_credits` | 用户实际扣减积分 |
| `channel_id` / `model` | 实际命中的渠道与模型，对账时不能按"最优价"估算 |

**`wallet_transaction`**

| 字段 | 说明 |
| --- | --- |
| `usage_record_id` | 消费类流水必须回填，保证每笔扣费可追溯到一次调用 |
| `amount` / `balance` | 变动值与变动后余额，只追加不修改 |

## 4. 关系说明

```text
sys_user 1 ── n ai_task 1 ── n ai_task_run
    │
    ├── 1 ── 1 wallet_account 1 ── n wallet_transaction
    ├── 1 ── n biz_order / recharge_order
    ├── 1 ── n user_subscription
    ├── 1 ── n ai_skill / ai_mcp_server
    └── 1 ── n artifact / usage_record
```

- 所有用户维度查询必须带 `user_id` 条件；
- 任务运行实例不做逻辑删除，依靠归档策略控制数据量；
- 订单/支付/钱包流水只追加不修改，状态变更通过新增状态记录或版本字段实现。

## 5. 与前端演示数据的关系

- 前端演示层（`frontend/src/mock`）并非数据库的镜像：它按页面组织数据，统一存放在浏览器 `localStorage`；
- 两者的业务字段命名保持相近（钱包、流水、订单、订阅等），便于后续把 mock 的 `load/save` 逐步替换为 `api/` 调用；
- 后端表结构以本文档与 `backend/src/main/resources/db/schema.sql` 为准；
- 新增表或字段时，需同步更新 `schema.sql`、本文档，并在对应 Mock 模块中补齐演示数据。
