# 接口文档

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://localhost:8080/api`（开发环境经 Vite 代理为 `/api`） |
| 数据格式 | `application/json; charset=UTF-8` |
| 认证方式 | `Authorization: Bearer <token>` |
| HTTP 状态 | 统一返回 200，业务结果由响应体 `code` 表达 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`，`LocalDate` 为 `yyyy-MM-dd`，时区 `Asia/Shanghai` |
| 在线文档 | Knife4j：`/api/doc.html`；OpenAPI：`/api/v3/api-docs` |

user 端请求收到 401 时会自动调用 `/auth/refresh` 刷新并重放原请求一次；刷新失败则清理登录态并跳转登录页。管理后台使用独立令牌，不参与用户端刷新流程。

### 1.1 统一响应

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

### 1.2 错误码

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录或登录已过期 |
| 403 | 无操作权限 |
| 500 | 操作失败 |
| 5000 | 系统内部错误 |
| 2001 | 用户名或密码错误 |
| 2002 | 账号已被禁用 |
| 2003 | 用户不存在 |
| 2004 | 登录失败次数过多，锁定 5 分钟 |
| 4001 | 请求体不可读 |
| 4002 | 参数类型不匹配 |
| 7001 | 定时任务不存在 |
| 7002 | 无权操作该任务 |
| 7003 | 任务状态仅支持 ENABLED / DISABLED |
| 7004 | 任务调度配置不合法 |
| 7005 | 任务并发修改冲突 |

未知异常统一返回 `5000`；请求体不可读、参数类型不匹配等客户端错误不会再落入 `5000`。

### 1.3 Mock 模式说明

开发环境前端默认启用 Mock 层（`frontend/src/mock`），通过 Axios 自定义 adapter 在浏览器内直接响应以下路径，不经过后端：

| 路径 | Mock 行为 |
| --- | --- |
| `POST /auth/login` | 使用内置演示账号 `demo@lingxi.local / lingxi-demo-2026`，签发本地令牌 |
| `POST /auth/email-code` | 生成 6 位验证码并写入 `localStorage`，不发送邮件 |
| `POST /auth/register` | 注册到浏览器本地账号库 |
| `GET /auth/profile` | 返回当前本地登录用户 |
| `/agent/tasks*` | 任务管理的本地实现，数据保存在 `lingxi-mock-tasks` |

- 这些路径仅用于界面演示，**不属于后端契约**，关闭 Mock 后由真实接口替代；
- Mock 模式下未命中的 `/api` 请求返回 `data: null`，页面改用本地演示数据渲染；
- 管理后台不发起 `/api` 请求，直接读写 `localStorage`；
- 关闭方式：设置 `VITE_MOCK=false` 后重启开发服务器，或生产构建时指定该变量。

## 2. 已实现接口

### 2.1 健康检查

`GET /health`（无需认证）

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "status": "UP",
    "service": "lingxi-backend",
    "version": "0.1.0",
    "time": "2026-11-17 15:00:00"
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

### 2.2 登录

`POST /auth/login`（无需认证）

请求：

```json
{
  "username": "admin",
  "password": "Admin@123"
}
```

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 720,
    "user": {
      "id": 1,
      "username": "admin",
      "nickname": "演示管理员",
      "role": "ADMIN"
    }
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：用户名或密码错误返回 `2001`；账号被禁用返回 `2002`；同一用户名连续 5 次失败后锁定 5 分钟，期间返回 `2004`。

### 2.3 注销

`POST /auth/logout`

请求头：

```text
Authorization: Bearer <token>
```

说明：幂等接口。携带有效令牌时，按令牌剩余有效期加入 Redis 黑名单；未携带、格式错误或已过期的令牌均直接返回成功，不会返回 401。

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": null,
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：仅服务端异常返回 `5000`。

### 2.4 刷新令牌

`POST /auth/refresh`

请求头：

```text
Authorization: Bearer <token>
```

说明：旧令牌未过期时签发新令牌，旧令牌按剩余有效期立即加入黑名单。响应 `data` 为 `{ token, expiresIn }`，`expiresIn` 单位为分钟。

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 720
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：

| 场景 | code |
| --- | --- |
| 缺少 `Authorization` 或不是 Bearer 格式 | 401 |
| 令牌已过期、签名非法或已被注销 | 401 |
| 服务端异常 | 5000 |

### 2.5 当前用户

`GET /auth/profile`

请求头：

```text
Authorization: Bearer <token>
```

响应 `data`：

```json
{
  "id": 1,
  "username": "admin",
  "nickname": "演示管理员",
  "role": "ADMIN"
}
```

### 2.6 任务列表

`GET /agent/tasks?page=1&size=20`

查询参数：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，默认 `1`，小于 `1` 时按 `1` 处理 |
| `size` | 每页条数，默认 `20`，最大 `100` |

响应 `data` 仍为当前页任务数组（不是分页对象）；MyBatis-Plus 分页 `maxLimit=100`。`page` / `size` 传入非数字时返回 `4002`。

```json

    "id": 1,
    "name": "每日 AI 资讯汇总",

    "model": "gpt-4o",
    "runLocation": "CLOUD",
    "timezone": "Asia/Shanghai",
    "scheduleType": "DAILY",
    "cronExpr": null,
    "intervalMinutes": 60,
    "executeTime": "09:00",
    "weekDays": null,
    "jitterSeconds": 30,
    "maxRounds": 50,
    "status": "ENABLED",
    "lastRunAt": null,
    "nextRunAt": null,
    "runCount": 0,
    "lastOutput": null,
    "createdAt": "2026-11-17 14:00:00"
```

### 2.7 新建任务

`POST /agent/tasks`

请求：

```json
{
  "name": "每日 AI 资讯汇总",
  "promptTemplate": "总结 {{date}} 的 AI 行业资讯，这是第 {{run_count}} 次运行。",
  "model": "gpt-4o",
  "runLocation": "CLOUD",
  "timezone": "Asia/Shanghai",
  "scheduleType": "DAILY",
  "executeTime": "09:00",
  "weekDays": null,
  "jitterSeconds": 30,
  "maxRounds": 50
}
```

字段约束：

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| name | 是 | ≤ 128 字符 |
| promptTemplate | 是 | ≤ 20000 字符，支持 `{{date}}` / `{{run_count}}` / `{{last_output}}` |
| model | 是 | 执行模型标识 |
| runLocation | 否 | `CLOUD` / `LOCAL`，默认 `CLOUD` |
| timezone | 否 | IANA 时区，默认 `Asia/Shanghai` |
| scheduleType | 否 | `INTERVAL` / `HOURLY` / `DAILY` / `WEEKLY` / `CRON`，默认 `DAILY` |
| cronExpr | 条件 | `CRON` 模式必填 |
| intervalMinutes | 条件 | `INTERVAL` 模式必填，≥ 1 |
| executeTime | 否 | `HH:mm`，默认 `09:00` |
| weekDays | 否 | `1-7` 逗号分隔，`WEEKLY` 模式缺省为 `1` |
| jitterSeconds | 否 | 0-60，默认 0 |
| maxRounds | 否 | 1-50，默认 50 |

调度配置非法返回 `7004`；请求体 JSON 无法解析返回 `4001`，字段类型不匹配返回 `4002`。

### 2.8 更新任务

`PUT /agent/tasks/{id}`

请求体字段同新建，均为可选；为空表示不修改。调度相关字段会重新做组合校验（cron 表达式、时区、`weekDays` 1-7 等），非法配置返回 `7004`；读取后任务状态已被其他请求修改时返回 `7005`，需刷新后重试。

### 2.9 启停任务

`PATCH /agent/tasks/{id}/status`

```json
{
  "status": "DISABLED"
}
```

`status` 仅支持 `ENABLED` / `DISABLED`；并发修改冲突返回 `7005`。

### 2.10 删除任务

`DELETE /agent/tasks/{id}`

逻辑删除；运行实例保留（后续 B7 运行历史使用）。

## 3. 规划中的接口分组

| 模块 | 前缀 | 典型接口 |
| --- | --- | --- |
| B1 | `/auth`、`/users` | 注册、改密、用户列表（管理端） |
| B2 | `/models`、`/chat`、`/keys` | 模型目录、对话补全、API Key 管理 |
| B3 | `/orders` | 订单创建/查询/取消 |
| B4 | `/wallet` | 余额、流水、冻结/解冻 |
| B5 | `/subscriptions` | 套餐、订阅、续费 |
| B6 | `/payments`、`/redeem` | 支付下单、回调、兑换码 |
| B7 | `/agent/tasks`、`/agent/runs` | 任务管理、手动运行、运行详情、取消 |
| B8 | `/artifacts` | 产物上传、列表、下载签名 |
| B9 | `/usages` | 用量明细、聚合统计 |
| B10 | `/admin` | 用户、订单、内容管理 |
| B11 | `/reports` | 营收、留存、用量报表 |
| B12 | `/browser-devices` | 设备配对、心跳、任务下发（WebSocket） |

> 上述分组均已有对应的前端演示页面（mock 数据），但后端接口尚未实现。实现时以本文档的响应结构、错误码与鉴权约定为准，并同步补充具体接口章节。

新增接口时必须同步更新本文档，并保持统一响应结构与错误码约定。
