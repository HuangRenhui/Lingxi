# 接口文档

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://localhost:8080/api`（开发环境经 Vite 代理为 `/api`） |
| 数据格式 | `application/json; charset=UTF-8` |
| 认证方式 | `Authorization: Bearer <token>` |
| HTTP 状态 | 统一返回 200，业务结果由响应体 `code` 表达 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`，`LocalDate` 为 `yyyy-MM-dd`，时区 `Asia/Shanghai` |
| 在线文档 | Knife4j：`/api/doc.html`；OpenAPI：`/api/v3/api-docs` |

user 端请求收到 401 时会自动调用 `/auth/refresh` 刷新并重放原请求一次；刷新失败则清理登录态并跳转登录页。管理后台使用独立令牌，不参与用户端刷新流程。

### 1.1 统一响应

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

### 1.2 错误码

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录或登录已过期 |
| 403 | 无操作权限 |
| 500 | 操作失败 |
| 5000 | 系统内部错误 |
| 2001 | 用户名或密码错误 |
| 2002 | 账号已被禁用 |
| 2003 | 用户不存在 |
| 2004 | 登录失败次数过多，锁定 5 分钟 |
| 4001 | 请求体不可读 |
| 4002 | 参数类型不匹配 |
| 7001 | 定时任务不存在 |
| 7002 | 无权操作该任务 |
| 7003 | 任务状态仅支持 ENABLED / DISABLED |
| 7004 | 任务调度配置不合法 |
| 7005 | 任务并发修改冲突 |
| 8401 / 8402 | 技能不存在 / 无权操作该技能 |
| 8501 / 8502 | 连接器不存在 / 无权操作该连接器 |
| 8601 / 8602 | 产物不存在 / 无权操作该产物 |
| 8701 / 8702 | 订单不存在 / 无权操作该订单 |
| 8703 | 订单状态不支持该操作 |
| 8704 | 当前状态不允许修改订单 |
| 9001-9004 | 管理端用户相关错误 |

未知异常统一返回 `5000`；请求体不可读、参数类型不匹配等客户端错误不会再落入 `5000`。

### 1.3 Mock 模式说明

开发环境前端默认启用 Mock 层（`frontend/src/mock`），通过 Axios 自定义 adapter 在浏览器内直接响应以下路径，不经过后端：

| 路径 | Mock 行为 |
| --- | --- |
| `POST /auth/login` | 使用内置演示账号 `demo@lingxi.local / lingxi-demo-2026`，签发本地令牌 |
| `POST /auth/email-code` | 生成 6 位验证码并写入 `localStorage`，不发送邮件 |
| `POST /auth/register` | 注册到浏览器本地账号库 |
| `GET /auth/profile` | 返回当前本地登录用户 |
| `/agent/tasks*` | 任务管理的本地实现，数据保存在 `lingxi-mock-tasks` |

- 这些路径仅用于界面演示，**不属于后端契约**，关闭 Mock 后由真实接口替代；
- Mock 模式下未命中的 `/api` 请求返回 `data: null`，页面改用本地演示数据渲染；
- 管理后台不发起 `/api` 请求，直接读写 `localStorage`；
- 关闭方式：设置 `VITE_MOCK=false` 后重启开发服务器，或生产构建时指定该变量。

## 2. 已实现接口

### 2.1 健康检查

`GET /health`（无需认证）

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "status": "UP",
    "service": "lingxi-backend",
    "version": "0.1.0",
    "time": "2026-11-17 15:00:00"
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

### 2.2 登录

`POST /auth/login`（无需认证）

请求：

```json
{
  "username": "admin",
  "password": "<部署时设置的管理员口令>"
}
```

> 口令不在文档中出现：数据库里只保存 BCrypt 哈希，初始演示账号见 `db/data.sql` 顶部说明，
> 生产环境必须在首次部署后立即重置。

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 720,
    "user": {
      "id": 1,
      "username": "admin",
      "nickname": "演示管理员",
      "role": "ADMIN"
    }
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：用户名或密码错误返回 `2001`；账号被禁用返回 `2002`；同一用户名连续 5 次失败后锁定 5 分钟，期间返回 `2004`。

### 2.3 注销

`POST /auth/logout`

请求头：

```text
Authorization: Bearer <token>
```

说明：幂等接口。携带有效令牌时，按令牌剩余有效期加入 Redis 黑名单；未携带、格式错误或已过期的令牌均直接返回成功，不会返回 401。

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": null,
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：仅服务端异常返回 `5000`。

### 2.4 刷新令牌

`POST /auth/refresh`

请求头：

```text
Authorization: Bearer <token>
```

说明：旧令牌未过期时签发新令牌，旧令牌按剩余有效期立即加入黑名单。响应 `data` 为 `{ token, expiresIn }`，`expiresIn` 单位为分钟。

响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 720
  },
  "timestamp": "2026-11-17 15:00:00",
  "success": true
}
```

错误场景：

| 场景 | code |
| --- | --- |
| 缺少 `Authorization` 或不是 Bearer 格式 | 401 |
| 令牌已过期、签名非法或已被注销 | 401 |
| 服务端异常 | 5000 |

    "executeTime": "09:00",
    "weekDays": null,
    "jitterSeconds": 30,
    "maxRounds": 50,

### 2.7 新建任务

`POST /agent/tasks`

请求：

```json
{
  "name": "每日 AI 资讯汇总",
  "promptTemplate": "总结 {{date}} 的 AI 行业资讯，这是第 {{run_count}} 次运行。",
  "model": "gpt-4o",
  "runLocation": "CLOUD",
  "timezone": "Asia/Shanghai",
  "scheduleType": "DAILY",
  "executeTime": "09:00",
  "weekDays": null,
  "jitterSeconds": 30,
  "maxRounds": 50
}
```

字段约束：

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| name | 是 | ≤ 128 字符 |
| promptTemplate | 是 | ≤ 20000 字符，支持 `{{date}}` / `{{run_count}}` / `{{last_output}}` |
| model | 是 | 执行模型标识 |
| runLocation | 否 | `CLOUD` / `LOCAL`，默认 `CLOUD` |
| timezone | 否 | IANA 时区，默认 `Asia/Shanghai` |
| scheduleType | 否 | `INTERVAL` / `HOURLY` / `DAILY` / `WEEKLY` / `CRON`，默认 `DAILY` |
| cronExpr | 条件 | `CRON` 模式必填 |
| intervalMinutes | 条件 | `INTERVAL` 模式必填，≥ 1 |
| executeTime | 否 | `HH:mm`，默认 `09:00` |
| weekDays | 否 | `1-7` 逗号分隔，`WEEKLY` 模式缺省为 `1` |
| jitterSeconds | 否 | 0-60，默认 0 |
| maxRounds | 否 | 1-50，默认 50 |

调度配置非法返回 `7004`；请求体 JSON 无法解析返回 `4001`，字段类型不匹配返回 `4002`。

### 2.8 更新任务

`PUT /agent/tasks/{id}`

请求体字段同新建，均为可选；为空表示不修改。调度相关字段会重新做组合校验（cron 表达式、时区、`weekDays` 1-7 等），非法配置返回 `7004`；读取后任务状态已被其他请求修改时返回 `7005`，需刷新后重试。

### 2.9 启停任务

`PATCH /agent/tasks/{id}/status`

```json
{
  "status": "DISABLED"
}
```

`status` 仅支持 `ENABLED` / `DISABLED`；并发修改冲突返回 `7005`。

### 2.10 删除任务

`DELETE /agent/tasks/{id}`

逻辑删除；运行实例保留（后续 B7 运行历史使用）。

### 2.13 新建应用

### 2.16 API Key 列表

`GET /api-keys?page=1&size=20`

仅返回当前用户的密钥，响应只含 `keyPrefix` 掩码前缀，不返回明文。

### 2.17 创建 API Key

`POST /api-keys`

```json
{ "name": "本地调试" }
```

响应额外包含 `key` 字段，为完整明文密钥（`lx_` 开头，共 35 位），仅本次返回；服务端只保存 SHA-256 摘要与前缀。

### 2.18 更新 API Key

`PUT /api-keys/{id}`

字段均可选：`name`（≤64）、`status`（1 启用 / 0 禁用）。不存在返回 `8101`，越权返回 `8102`。

### 2.19 删除 API Key

`DELETE /api-keys/{id}`

逻辑删除；错误码同上。

字段均可选，仅更新传入的字段；`title` / `url` 传入空白返回 `400`；`favorite` / `trashed` 仅支持 `0` / `1`；`status` 仅支持 `PENDING` / `APPROVED` / `REJECTED`。错误码同详情。

### 2.48 删除产物

`DELETE /artifacts/{id}`

逻辑删除；产物不存在返回 `8601`，非本人创建返回 `8602`。

### 2.49 我的订单列表

`GET /orders`

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 否 | 页码，默认 1 |
| `size` | 否 | 每页条数，默认 20，上限 100 |
| `status` | 否 | `PENDING` / `PAID` / `CANCELLED` / `REFUNDING` / `REFUNDED` |
| `type` | 否 | `RECHARGE` / `SUBSCRIPTION` / `CONSUME` / `REDEEM` |
| `keyword` | 否 | 订单号或描述模糊匹配 |

响应示例：

```json
[
  {
    "id": 1,
    "orderNo": "LX202611181030150001",
    "description": "专业版订阅 · 月付",
    "type": "SUBSCRIPTION",
    "amount": 68.000000,
    "payMethod": "ALIPAY",
    "status": "PAID",
    "paidAt": "2026-11-18 10:30:15",
    "createdAt": "2026-11-18 10:30:15",
    "updatedAt": "2026-11-18 10:31:02"
  }
]
```

筛选值不在枚举范围内返回 `400`。

### 2.50 订单详情

`GET /orders/{id}`

订单不存在返回 `8701`，非本人订单返回 `8702`。

### 2.51 新建订单

`POST /orders`

```json
{
  "description": "积分充值",
  "type": "RECHARGE",
  "amount": 200,
  "payMethod": "ALIPAY"
}
```

`description` 必填且不超过 128 字符；`amount` 必填且不得为负数；`type` 缺省为 `CONSUME`；新建订单一律为 `PENDING`，订单号由服务端生成。

### 2.52 更新订单

`PUT /orders/{id}`

仅待支付订单可修改，且只开放 `description` 与 `payMethod`；非待支付状态返回 `8704`。错误码同详情。

### 2.53 变更订单状态

`PATCH /orders/{id}/status`

```json
{ "status": "CANCELLED" }
```

用户侧当前仅支持取消待支付订单；目标状态非 `CANCELLED` 返回 `400`，订单非待支付状态返回 `8703`。支付与退款状态由后续支付回调接口推进。

### 2.54 删除订单

`DELETE /orders/{id}`

逻辑删除；仅 `PENDING` / `CANCELLED` 订单可删除，其余状态返回 `8703`；订单不存在返回 `8701`，非本人订单返回 `8702`。

### 2.55 我的钱包账户

`GET /wallet`

响应示例：

```json
{
  "balance": 128.600000,
  "frozen": 6.400000,
  "totalRecharge": 500.000000,
  "totalSpent": 371.400000
}
```

尚未开户的用户返回全 0 账户。钱包为只读视图，余额变动由订单支付、兑换码与退款等业务驱动。

### 2.56 我的钱包流水

`GET /wallet/transactions`

查询参数：`page`（默认 1）、`size`（默认 20，上限 100）、`type`（`RECHARGE` / `CONSUME` / `REWARD` / `REFUND` / `FREEZE` / `UNFREEZE`）。

响应示例：

```json
[
  {
    "id": 1,
    "type": "CONSUME",
    "amount": -2.100000,
    "balance": 128.600000,
    "note": "Kling · 视频生成",
    "createdAt": "2026-11-19 20:14:00"
  }
]
```

流水只追加不修改；`type` 非法返回 `400`。

## 3. 规划中的接口分组

| 模块 | 前缀 | 典型接口 |
| --- | --- | --- |
| B1 | `/auth`、`/users` | 注册、改密、用户列表（管理端） |
| B2 | `/models`、`/chat`、`/keys` | 模型目录、对话补全、API Key 管理 |
| B3 | `/orders` | 订单创建/查询/取消（已实现基础管理） |
| B4 | `/wallet` | 余额、流水（已实现查询） |
| B5 | `/subscriptions` | 套餐、订阅、续费 |
| B6 | `/payments`、`/redeem` | 支付下单、回调、兑换码 |
| B7 | `/agent/tasks`、`/agent/runs` | 任务管理、手动运行、运行详情、取消 |
| B9 | `/usages` | 用量明细、聚合统计 |
| B10 | `/admin` | 用户、订单、内容管理 |
| B11 | `/reports` | 营收、留存、用量报表 |
| B12 | `/browser-devices` | 设备配对、心跳、任务下发（WebSocket） |

> B3/B4 已提供基础接口，B5 与支付回调、余额变动能力随 B5/B6 补齐；B2、B5-B6、B9-B12 仍待实现。实现时以本文档的响应结构、错误码与鉴权约定为准，并同步补充具体接口章节。

新增接口时必须同步更新本文档，并保持统一响应结构与错误码约定。
